01What Is a String? — Unicode, not ASCII▸

Plainly: any text — "Hello World", "My name is Nitish" — is a string. Structurally: a collection of characters.

★ The official definition — and why it matters
"In Python specifically, strings are a sequence of Unicode characters" — not just "characters." Early 8-bit machines could only represent 256 characters (ASCII) — fine for English, but far too small once people needed to type in other languages. The fix: a 16-bit character set (Unicode, 2¹⁶ combinations) that can hold characters from many languages — and emojis. Python strings are Unicode-based, not ASCII-based — an explicitly flagged, important distinction.
02Creating Strings▸ 
s = 'hello'
s = "hello"
# multiline strings
s = '''hello'''
s = """hello"""
s = str('hello')
print(s)

"it's raining outside"   # double quotes let the apostrophe through
★ Why both single AND double quotes exist
Try wrapping It's raining outside entirely in single quotes — Python reads the string as ending right at the apostrophe in "It's", breaking the rest. Fix: wrap the whole thing in double quotes instead, so the inner apostrophe is just a literal character (and vice-versa for a sentence containing a double quote). Triple quotes (either kind) are for multi-line strings — e.g. capturing a whole blog post a user typed.

Raw strings exist too, but were explicitly deferred to a later interview-prep class.

03Indexing▸ 
s = 'hello world'
print(s[41])     # IndexError: string index out of range

s = 'hello world'
print(s[-3])      # 'r' -> negative indexing
★ Remember — the summary he gave
Positive indexing: left to right, starts from 0. Negative indexing: right to left, starts from -1 (last character), -2 (second-last), and so on. Going past the string's length in either direction → IndexError.
04Slicing — including the negative-step gotcha▸

Slicing extracts more than one character at once: s[start:end], end excluded — same shape as strings you've already seen with lists.

s = 'hello world'
print(s[6:0:-2])     # 'wol'
print(s[::-1])        # 'dlrow olleh' -> the famous one-liner to reverse a string
print(s[-1:-6:-1])    # 'dlrow'
⚠ The rule everyone trips on — negative step direction
"Whenever you take a negative step, the first number should be bigger than the second — otherwise it won't work." That's why s[6:0:-2] starts at 6 and walks down to (excluding) 0, taking every second character on the way → 'wol'. Try to slice with the numbers the "normal" way round using a negative step and you get an empty result.
⚠ Excluding the end you actually wanted
To grab "World" from "hello world" via negative indices, s[-5:-1] looks right but excludes the very last character ('d'), giving "Worl". Omit the end index entirely — s[-5:] — to include everything to the end.
★ The one-liner worth memorizing
s[::-1] reverses any string in one line — no loop needed, unlike C or Java. You'll reach for this constantly.
05Editing & Deleting — Strings Are Immutable▸ 
s = 'hello world'
s[0] = 'H'
# TypeError: 'str' object does not support item assignment

s = 'hello world'
del s
print(s)
# NameError: name 's' is not defined

s = 'hello world'
del s[-1:-5:2]
print(s)
# TypeError: 'str' object does not support item deletion
★ Very, very important — flagged twice by the instructor
"Once you've created a string in Python, you cannot change it." This is called immutability — like how a virus "mutates" (changes), an immutable type can't. You can't edit a character in place, and you can't delete part of a string either — trying either throws a TypeError. del s only removes the variable name, not necessarily the string data itself at the memory level (deeper coverage saved for a future class).
06Operations on Strings▸

Arithmetic — only + and *

print('delhi' + ' ' + 'mumbai')    # concatenation
print('delhi'*5)                   # repetition
print('*'*50)                      # handy for building separators/table borders

Only + and * work on strings — subtraction, division, modulus don't apply.

Relational — lexicographic (dictionary-order) comparison

'delhi' != 'delhi'      # False

'mumbai' > 'pune'        # False -> 'm' comes before 'p' in dictionary order
'Pune' > 'pune'           # False -> capital letters have SMALLER ASCII values
★ Not character count — dictionary order
"Mumbai" has more letters than "Pune", but that's irrelevant — comparison works like an Oxford dictionary: whichever word would appear later is "bigger". Since "Mumbai" comes before "Pune" alphabetically, it's the smaller one. Comparisons are ultimately done on ASCII values, and capital letters sit at lower ASCII values than their lowercase counterparts — so 'Pune' > 'pune' is False.

Logical — the and/or quirk (interview favorite)

'hello' and 'world'    # 'world'
'hello' or 'world'     # 'hello'
'' and 'world'          # ''
'' or 'world'           # 'world'
not 'hello'             # False
◆ The rule to memorize (genuinely asked in interviews)
A non-empty string is truthy; an empty string '' is falsy. With and, Python can't settle the result from the first operand alone (if it's truthy) — it must check the second operand too, so the second string is what gets returned when both are truthy. With or, the moment the first operand is truthy, Python already knows the result — so the first string is returned without even checking the second. (This is short-circuit evaluation — Python returns the actual operand, not a plain True/False.)

Loops & membership

for i in 'hello':
  print(i)              # prints each character on its own line

for i in 'delhi':
  print('pune')          # prints 'pune' 5 times -> once per character in 'delhi'

'D' in 'delhi'            # False -> case-sensitive!

Strings are iterable, so loops just work — the loop runs once per character, regardless of what you actually print inside it.

07Common Functions — len / max / min / sorted▸ 
len('hello world')                      # 11 (spaces count)
max('hello world')                      # 'w' -> highest ASCII value
min('hello world')                      # ' ' -> space has a low ASCII value
sorted('hello world', reverse=True)     # returns a LIST, not a string

These four work across strings, lists, tuples, sets and dicts — the same functions will resurface everywhere. min() on "hello world" quietly returns a space character — easy to miss since it's invisible in output.

08Case Functions — and proof they don't mutate▸ 
s = 'hello world'
print(s.capitalize())    # 'Hello world'
print(s)                  # 'hello world' -> s itself is UNCHANGED

s.title()                 # 'Hello World'
s.upper()                 # 'HELLO WORLD'
'Hello Wolrd'.lower()      # 'hello wolrd'
'HeLlO WorLD'.swapcase()   # 'hElLo wORld'
◆ The exact interview answer for "but these functions DO change the string?"
A student asked this directly. The proof: call s.capitalize(), then print s again — s is still the original. Every one of these functions builds a brand-new string in memory and hands that back to you; none of them touch the original. This is the live confirmation of immutability from section 09 — use it as the answer if this comes up in an interview.

capitalize() — handy for names stored lowercase in a database, capitalized only when displayed. title() — blog-heading style, first letter of every word capitalized.

09count / find / index▸ 
'my name is nitish'.count('i')     # 3

'my name is nitish'.find('x')       # -1  -> not found, no error
'my name is nitish'.index('x')      # ValueError: substring not found
★ find vs. index — same success case, different failure case
Both return the position of a substring when found. The difference is only what happens when it's not found: find() returns -1 quietly; index() raises a ValueError. Use find() when absence is a normal case you want to handle gracefully without a try/except; use index() when you're confident the substring must exist and want a hard failure otherwise.
10startswith / endswith▸ 
'my name is nitish'.endswith('sho')      # False
'my name is nitish'.startswith('1my')     # False

Checks whether a string starts or ends with a given substring — returns a plain boolean.

11format()▸ 
name = 'nitish'
gender = 'male'

'Hi my name is {1} and I am a {0}'.format(gender,name)
# 'Hi my name is nitish and I am a male'
★ Positional index, not argument order
{0} and {1} refer to argument position, not template position — whatever was passed first to .format() always fills every {0} in the template, wherever it appears. This lets you control layout independent of argument order.

Preferred over old C-style % formatting — "the industry doesn't work on that much" anymore.

12isalnum / isalpha / isdigit / isidentifier▸ 
'nitish1234%'.isalnum()      # False -> % is not alphanumeric
'nitish'.isalpha()            # True
'123abc'.isdigit()            # False -> contains letters
'first-name'.isidentifier()    # False -> hyphen not allowed
'name1'.isidentifier()         # True
'1name'.isidentifier()         # False -> can't start with a digit

"Criteria-testing" functions — each checks whether the whole string satisfies one specific rule.

13split() / join()▸ 
'hi my name is nitish'.split()          # ['hi', 'my', 'name', 'is', 'nitish']

" ".join(['hi', 'my', 'name', 'is', 'nitish'])   # 'hi my name is nitish'
★ Memory aid
"split is for breaking apart, join is for putting together." split() defaults to breaking on whitespace but can split on any custom character. Swap the "glue" string in join() (e.g. "-".join(...)) to change how pieces get reconnected. Flagged as probably the single most-used string function of them all.
14replace() / strip()▸ 
'hi my name is nitish'.replace('nitisrgewrhgh','campusx')
# 'hi my name is nitish' -> no match found, nothing changes, no error

'nitish                           '.strip()
# 'nitish' -> trailing/leading whitespace removed

replace(old, new) swaps a substring; searching for something that doesn't exist just leaves the string unchanged (no error, unlike index()). strip() is the real-world fix for the "extra spaces from a glitchy keyboard/copy-paste" problem — cleans up user-entered text before it hits a database.

◆8 Worked Practice Programs (Supplementary Session)▸

Class ran out of time before reaching these live, so the instructor recorded a short supplementary walkthrough covering exactly these — treat them as your core string practice set.

1. String length without len()

s = input('enter the string')
counter = 0
for i in s:
  counter += 1
print('length of string is', counter)

Loop character by character, incrementing a counter — the same "counter variable" pattern from the very first day.

2. Extract username from an email

s = input('enter the email')
pos = s.index('@')
print(s[0:pos])

Find the @'s position with index(), then slice everything before it. "The basic idea is just find the position of @, and then slice."

3. Count frequency of a given character

s = input('enter the string')
term = input('what would you like to search for')

counter = 0
for i in s:
  if i == term:
    counter += 1

print('frequency', counter)

4. Remove a character from a string

s = input('enter the string')
term = input('what would you like to remove')

result = ''
for i in s:
  if i != term:
    result = result + i

print(result)
★ Ties directly back to immutability
Since strings can't be edited in place, "removing" a character really means building a brand-new string that skips it — start with an empty result, loop through the original, and only append characters that aren't the one to remove.

5. Palindrome check

s = input('enter the string')
flag = True
for i in range(0, len(s)//2):
  if s[i] != s[len(s) - i - 1]:
    flag = False
    print('Not a Palindrome')
    break

if flag:
  print('Palindrome')

Two-pointer idea: only loop to the halfway point, comparing character i from the front against its mirror len(s)-i-1 from the back. A flag starts True; the moment a mismatch is found, flip it to False, announce it, and break immediately — no need to keep checking. If the loop finishes with the flag still True, it's a palindrome.

6. Count words without split()

s = input('enter the string')
L = []
temp = ''
for i in s:
  if i != ' ':
    temp = temp + i
  else:
    L.append(temp)
    temp = ''

L.append(temp)
print(L)
★ Why the extra L.append(temp) after the loop
Building the current word into temp character by character; hitting a space means the word is complete — push it to the list and reset temp. But the very last word never gets followed by a space, so the loop alone would drop it — hence one final L.append(temp) after the loop ends, to flush whatever's left.

7. Convert to title case, without title()

s = input('enter the string')

L = []
for i in s.split():
  L.append(i[0].upper() + i[1:].lower())

print(" ".join(L))

For each word: capitalize just the first character (i[0].upper()) and lowercase everything after it (i[1:].lower()), then glue the words back together with join().

8. Convert an integer to a string, without str()

number = int(input('enter the number'))

digits = '0123456789'
result = ''
while number != 0:
  result = digits[number % 10] + result
  number = number//10

print(result)
print(type(result))
enter the number 345
345
<class 'str'>
★ Same digit-extraction trick from Session 2, now producing a string
digits is a lookup string holding every possible digit character at its matching index. number % 10 extracts the last digit as an int, and digits[...] converts that int into its character form — prepended to result (not appended!) since digits come out last-to-first. number // 10 shrinks the number each round, same as the sum-of-digits program.
★60-Second Cheat Sheet▸
Nested loops

Inner loop runs fully before outer loop advances — Cartesian-product shape

Pattern trick

Solve the ascending half first; descending starts at i-1, step -1

break vs continue

break = stop the whole loop · continue = skip just this round

for…else

else runs only if the loop finished WITHOUT a break

Unicode

Python strings are Unicode, not ASCII — handles any language + emoji

Negative-step slicing

First index must be bigger than the second, or you get nothing

Reverse a string

s[::-1] — the famous one-liner

Immutable

No item assignment, no item deletion — every "change" makes a new string

and / or on strings

and → 2nd operand (if both truthy) · or → 1st operand (if truthy)

find vs index

find → -1 if missing · index → raises ValueError

split / join

split breaks apart · join glues back together

format()

{0}/{1} = argument position, independent of template order
