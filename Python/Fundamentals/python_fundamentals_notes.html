01Why Python?▸

Before any syntax — why this language, and why it took over data science.

✎ The Mohabbatein analogy
Java's personality is like Amitabh Bachchan's character in Mohabbatein — strict, disciplined, rigid: write code exactly one way or you get an error. Python's personality is like Shah Rukh Khan's character in the same film — welcoming to beginners: "it's okay if you don't know how to code — come, make mistakes, and learn." Python is the easy-going, forgiving language.

"Batteries included"

This is the literal phrase used to define Python: a language with batteries included — tons of pre-built functionality (data types, functions, operators) so you're not writing everything from scratch. Reversing a string in C means writing your own loop; in Python it's a one-line slice. Philosophy: don't reinvent the wheel — a company cares whether your app works well, not how hard you worked to hand-build every piece.

Why Python specifically won data science

  1. Easy to learn — early data science was done by mathematicians/statisticians, not professional programmers. Java/C++ were too steep to pick up quickly, so Python won.
  2. Proximity with math — Python already had scientific-computing libraries (NumPy, SciPy) before the data-science boom.
  3. Snowball effect — more users → more libraries (Pandas, TensorFlow, Keras…) → bigger ecosystem → harder for other languages to catch up.
⚠ "But Python is slow…"
True — but the workaround is libraries like NumPy, whose array type is actually implemented in C underneath. You write Python syntax; the heavy lifting underneath runs at C speed. That's why ML-heavy code stays fast despite Python's reputation.
◆ Python vs R, compiled vs interpreted
Python vs R: R is strong in academia (stats, plotting); Python is the better general-purpose, industry choice. Aiming for an industry job → Python. Planning a Masters/PhD → you'll likely need R too, since most researchers use it.

Compiled vs interpreted: compiled languages (Java, C) convert the whole program to machine code at once and tend to be faster; interpreted/scripting languages (Python, JS, PHP) run line by line and tend to be slower.
02Python Output — print()▸

Core idea If you see word() — a name followed by round brackets — that's your visual cue it's a function: you feed input inside the brackets and get output back.

  • Python is case-sensitive — always print, never Print.
  • Text needs quotes. print(Salman Khan) errors because Python can't tell if that's a variable or plain text — quotes are how you say "this is a string".
  • Any data type can be printed, and multiple values can be printed at once, comma-separated.
print('Hello World')
print('salman khan')
# print(salman khan)     -> SyntaxError: no quotes = not valid text
print(7)
print(7.7)
print(True)
print('Hello', 1, 4.5, True)
Hello World
salman khan
7
7.7
True
Hello 1 4.5 True

sep — what goes between multiple items

Default separator between comma-separated items is a space. Override it with sep.

print('Hello', 1, 4.5, True, sep='/')
Hello/1/4.5/True

end — whether output moves to a new line

Default value of end is \n (newline) — that's why two separate print() calls land on separate lines. Override it to change that.

print('hello')
print('world')
# hello
# world

print('hello', end='-')
print('world')
# hello-world
★ Remember — the 4-step recap
1) Print any data type. 2) Print multiple things at once with commas. 3) Control what goes between them with sep. 4) Control the line break after with end.

04Variables▸
"A variable is used wherever, at the time of writing the program, you don't know what value will go there in the future."

Example: a website prints "Hello, [username]" — you don't know in advance if it'll be Rahul, Rohit or Ankita, so a variable holds the slot that gets filled at runtime.

Python vs C/C++

C requires a type upfront: int name = 5;. Python just takes the value directly — name = 'nitish' — and figures out the type itself.

name = 'nitish'
print(name)

a = 5
b = 6
print(a + b)          # 11
◆ Interview question — dynamic typing
Dynamic typing: you never declare a variable's type — Python's interpreter infers it from the value (5→int, 5.5→float, 'Nitish'→str) automatically.
Static typing (the contrast): C, Java, C++ require the type to be declared up front.
◆ Interview question — dynamic binding
Static binding (C/C++/Java): once a variable's type is fixed, it can only ever hold that type for the rest of the program.
Dynamic binding (Python): the same variable name can hold an int now and a string later — there's no permanent attachment between a name and a type. (Some Java-background programmers dislike this — less type safety.) 
a = 5
print(a)
a = 'nitish'      # same variable, now a completely different type
print(a)

Multiple assignment styles

Recognize these in other people's code, even if you don't always use them:

a = 1
b = 2
c = 3
print(a, b, c)          # standard

a, b, c = 1, 2, 3
print(a, b, c)          # compressed — multiple vars, one line

a = b = c = 5
print(a, b, c)          # same value into all three at once

05Comments▸

A comment is a line the interpreter ignores completely — pure documentation for humans. Syntax: # followed by text.

# this is a comment
# second line
a = 4
b = 6   # like this
# second comment
print(a+b)
10
  • Python has no native multi-line comment — every line needs its own #. Editor "tricks" for pseudo multi-line comments exist, but real companies don't write code that way — skip them.
  • Comment placement: above the line (instructor's own preference, and what most companies do) or beside it — both fine.
✎ The batsman analogy — why comments matter
"A person who doesn't write comments but writes very good code is like a batsman who can hit a six off every ball but runs out his own batting partner." Build the comment-writing habit now — it's what makes you usable on a team later, not just a strong solo coder.
06Keywords & Identifiers▸

Why keywords exist — the compilation chain

You write code in English-like high-level language so any teammate can read it. But the machine only understands binary (1s and 0s). Converting your English-like code into binary is compilation — done by a compiler (Java, C, C++ — whole program at once) or an interpreter (Python, PHP — line by line).

The interpreter needs specific "signal words" to understand your intent — print tells it you want output, if/else tells it you want branching. These reserved signal words are keywords.

"These ~32 words are like the interpreter saying to you with folded hands: 'these are reserved just for me — please don't use them as variable names, or there'll be confusion.'"
★ Remember
Python has roughly 32–33 keywords (e.g. True, False, if, else…). No need to memorize the list — just know they exist, so you never accidentally name a variable print or if and get a confusing crash. You also can't invent your own new keywords.

Identifiers — naming rules

# You can't start with a digit
name1 = 'Nitish'
print(name1)

# You can use special chars -> _
_ = 'ntiish'
print(_)

# identifiers can not be a keyword
Nitish
ntiish
  • Can't start with a digit (1name is invalid, name1 is fine).
  • Underscore _ is allowed, including as a name on its own.
  • Can't be one of the reserved keywords.
07User Input▸
✎ Static vs. dynamic software
Static software just displays information — a calendar showing dates, no interaction. Dynamic software talks with the user — YouTube (search, comment), Ola (destination), Zomato (order). "99% of software today is dynamic," and that starts with knowing how to take input. 
input('Enter Email')
Enter Email [user types: nitish@gmail.com]
'nitish@gmail.com'
★ Remember
Calling input() with nothing inside shows a blank box — the user has no idea what to type. Always pass a prompt string: input('Enter your name: '). "As a programmer, it's your responsibility to always tell the user what they need to do."
08Type Conversion — the input() bug that teaches it▸
★ Habit worth building
"Programming happens first in your mind, then on the keyboard." Comment out the plan first (#take input, #add, #print result), then fill in code under each line.

The bug

fnum = int(input('enter first number'))
snum = int(input('enter second number'))
#print(type(fnum),type(snum))
result = fnum + snum
print(result)
print(type(fnum))
enter first number 56
enter second number 67
123
<class 'int'>

Before wrapping with int(), feeding in 56 and 67 gave 5667 — Python was doing string concatenation, not addition, because input() always returns type str.

◆ Why does input() always return a string?
Because string is the universal format — any value can be represented as a string (the number 4 as "4"), but not every string can become another type ("Kolkata" can't become an int). Since input() could receive anything, Python plays it safe and always stores it as str.

Implicit vs. Explicit conversion

print(5 + 5.6)              # 10.6  -> implicit: int+float, Python does it automatically
print(type(5), type(5.6))  # <class 'int'> <class 'float'>

print(4 + '4')              # TypeError! Python won't guess int + str

str(5)                      # explicit: int -> str
float(4)                    # explicit: int -> float  -> 4.0
KindWho does itExample
ImplicitPython, automatically5 + 5.6 → 10.6
ExplicitYou, with a functionint('4'), str(5), float(4)
⚠ Conversion isn't always allowed
You can't convert a complex number like 4+5j to int — it would mean discarding the imaginary part, i.e. losing information, which Python won't silently do. Rule of thumb: conversion only happens when nothing meaningful is lost.
◆ MCQ trap — conversion doesn't mutate the original
int(fnum) used inside an expression does not permanently change fnum — it creates a brand-new value used only in that expression. fnum stays whatever it was unless you explicitly reassign: fnum = int(fnum). Doing the conversion right at input time (fnum = int(input(...))) is the cleaner, more permanent approach — flagged as a common source of confusing 4-option exam questions.
09Literals▸

A variable is a container; a literal is the raw value you put inside it — in a = 2, the 2 is the literal.

Numeric literals — different notations

a = 0b1010     # Binary Literal
b = 100        # Decimal Literal
c = 0o310      # Octal Literal
d = 0x12c      # Hexadecimal Literal

float_1 = 10.5
float_2 = 1.5e2     # 1.5 * 10^2
float_3 = 1.5e-3    # 1.5 * 10^-3

x = 3.14j            # Complex Literal
print(a, b, c, d)
print(float_1, float_2, float_3)
print(x, x.imag, x.real)
✎ Where binary literals actually get used
The instructor's own background is robotics — 0b binary notation shows up there for port/hardware programming. "In normal (everyday) programming you probably won't need this."

Boolean literals — internally just numbers

a = True + 4
b = False + 10
print('a:', a)     # 5
print('b:', b)     # 10
★ Remember — MCQ trap
Internally, Python treats True as 1 and False as 0 — so they participate directly in math (True + 4 == 5). Don't get confused if a snippet mixes booleans into arithmetic.

The None literal

k = None
a = 5
b = 6
print('Program exe')

Unlike some languages, Python won't let you pre-declare a variable with no value at all — writing a bare name with nothing assigned throws an error. None is the placeholder that says "I need this variable, I just don't know its value yet" — handy when sketching out an ML algorithm's variables before you've decided what goes in each.
